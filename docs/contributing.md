# 贡献指南

感谢您对Mars Admin项目的关注！我们非常欢迎社区成员参与贡献，无论是代码、文档、测试还是问题反馈，都将帮助我们改进项目。本指南将帮助您了解如何参与项目贡献。

## 行为准则

参与本项目的所有贡献者都需要遵守以下行为准则：

- 尊重所有参与者，不论背景、经验水平或观点
- 接受建设性批评，并以专业方式回应
- 关注项目的最佳利益，而非个人利益
- 避免使用冒犯性语言或行为

## 贡献方式

您可以通过以下方式为Mars Admin项目做出贡献：

### 1. 提交问题（Issues）

如果您发现了bug或有新功能建议，请先查看现有的Issues，确保没有重复提交。创建新Issue时，请：

- 使用清晰的标题描述问题
- 提供详细的问题描述或功能建议
- 如果是bug，请提供复现步骤和环境信息
- 如可能，附上截图或错误日志

### 2. 提交代码（Pull Requests）

如果您想直接贡献代码，请遵循以下步骤：

1. Fork项目仓库到您的GitHub/Gitee账号
2. 克隆您的Fork到本地
   ```bash
   git clone https://github.com/YOUR_USERNAME/mars-admin.git
   ```
3. 创建新的分支
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. 进行代码修改
5. 提交您的更改
   ```bash
   git commit -m "feat: add some feature"
   ```
6. 推送到您的Fork
   ```bash
   git push origin feature/your-feature-name
   ```
7. 创建Pull Request到原仓库的master分支

### 3. 改进文档

文档对于项目的可用性至关重要。您可以通过以下方式改进文档：

- 修正错别字或语法错误
- 添加缺失的信息或示例
- 改进现有文档的清晰度和结构
- 翻译文档到其他语言

### 4. 测试

提高测试覆盖率对项目质量至关重要：

- 为现有功能编写单元测试
- 为新功能编写测试用例
- 进行集成测试和性能测试
- 报告测试过程中发现的问题

## 开发规范

### Git提交规范

提交信息请遵循以下格式：

```
<type>(<scope>): <subject>

<body>

<footer>
```

其中：

- `type`: 提交类型
  - `feat`: 新功能
  - `fix`: 修复Bug
  - `docs`: 文档更新
  - `style`: 代码风格调整（不影响代码逻辑）
  - `refactor`: 代码重构
  - `perf`: 性能优化
  - `test`: 测试相关
  - `chore`: 构建过程或辅助工具变动
- `scope`: 影响范围（可选）
- `subject`: 简短描述，不超过50个字符
- `body`: 详细描述（可选）
- `footer`: 关闭Issue等信息（可选）

示例：
```
feat(user): 添加用户导出功能

- 支持Excel导出
- 支持选择导出字段

Closes #123
```

### 代码风格

#### Java代码规范

- 遵循阿里巴巴Java开发手册规范
- 使用4个空格进行缩进，不使用Tab
- 类名使用PascalCase命名法（如`UserService`）
- 方法名和变量名使用camelCase命名法（如`getUserById`）
- 常量使用UPPER_SNAKE_CASE命名法（如`MAX_COUNT`）
- 所有公共方法必须有JavaDoc注释

#### TypeScript/Vue代码规范

- 使用2个空格进行缩进
- 使用单引号而非双引号
- 组件名使用PascalCase命名法（如`UserList.vue`）
- 变量和方法使用camelCase命名法
- 接口名前不加`I`前缀
- 使用ESLint和Prettier保持代码风格一致

### 分支管理

- `master`: 主分支，保持稳定可发布状态
- `develop`: 开发分支，最新的开发代码
- `feature/*`: 功能分支，用于开发新功能
- `bugfix/*`: 修复分支，用于修复非紧急bug
- `hotfix/*`: 热修复分支，用于修复紧急生产环境bug
- `release/*`: 发布分支，用于版本发布准备

## 开发流程

### 环境设置

请参考[环境准备](guide/prepare.md)和[本地开发](guide/development.md)章节设置开发环境。

### 开发步骤

1. **选择任务**：从Issues中选择一个任务，或提出新的功能/修复建议
2. **讨论方案**：在Issue中讨论实现方案，获得社区反馈
3. **开发功能**：按照开发规范进行编码
4. **编写测试**：为新功能或修复编写测试用例
5. **提交PR**：提交Pull Request并等待审核
6. **修改反馈**：根据审核反馈进行修改
7. **合并代码**：代码审核通过后，由维护者合并到主分支

### 测试要求

- 所有新功能必须有单元测试
- 修复bug时应添加能复现问题的测试用例
- 提交前运行所有测试，确保通过
- 保持或提高测试覆盖率

## 审核流程

所有代码贡献都需要经过审核才能合并到主分支：

1. 自动化检查：CI系统会自动运行测试和代码质量检查
2. 代码审核：至少一名项目维护者会审核代码变更
3. 讨论和修改：根据审核意见进行讨论和修改
4. 最终批准：满足要求后，维护者会批准并合并PR

## 版本发布

Mars Admin使用语义化版本控制（[SemVer](https://semver.org/)）：

- 主版本号（x.0.0）：不兼容的API变更
- 次版本号（0.x.0）：向后兼容的功能性新增
- 修订号（0.0.x）：向后兼容的问题修正
